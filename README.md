# GitHub Actions: Zero to Production 🚀

Welcome to the ultimate, hands-on repository for mastering **GitHub Actions** from scratch all the way to production-grade automation. This repository contains all the code samples, workflows, and configurations featured in the **GitHub Actions: Zero to Production** tutorial series on Medium and Hashnode.

---

## 📚 Series Curriculum & Code Navigator

This project is broken down into 5 sequential parts. Each folder inside this repo contains the exact workflow configurations, scripts, and example code covered in that specific chapter.

| Topic | Focus Areas |
| :--- | :--- |
| **Fundamentals & First Pipeline** | Actions core concepts, YAML structure, syntax validation |
| **Workflows In-Depth** | Complex triggers, conditions, output mapping |
| **Secrets, Permissions & Security** | fine-grained controls, encrypted secrets, hardening security |
| **Deployments & Cloud Shipping** | Protected environments, manual approval gates, deployment concurrency |
| **Advanced Production Patterns** | Reusable workflows, self-hosted runners |

---

## 🛠️ Repository Structure

```text
├── part1/                  # Fundamentals & First Pipeline
│   
├── part2/                  # Workflows In-Depth (Triggers, Conditions, Outputs)
│   
├── part3/                  # Secrets, Permissions & Pipeline Security
│   
├── part4/                  # Deployments, Environments & Approvals
│   
├── part5/                  # Reusable Workflows & Advanced Patterns
│   
└── README.md
```

> **Note for Testing:** GitHub Actions requires active workflows to reside inside a `.github/workflows/` directory to execute. The files in these `partX/` folders are production-ready code samples for you to study, copy, and place into your own project's `.github/` setup.

## 🚀 How to Use This Repository

1. **Fork this repository** to your own GitHub account to experiment with the configurations.
2. **Follow along with the articles** to understand the architectural "why" behind the code patterns.
3. **Copy-paste the snippets** from the respective `part/` folders into your own projects to accelerate your pipeline engineering.
